This is the central constraint driving the design below.
  - **Schema** (`supabase/migrations/20260930000000_create_announcements.sql`, run manually in the SQL Editor — the project is not linked to the Supabase CLI and no DB password is available, so it is NOT yet applied): `announcement_category` enum (`registration|speakers|agenda|sponsors|posters|general`) and an `announcements` table (`id/title/body/category/link_target/custom_url/published/created_at`). Added a partial index `(created_at desc) where published = true` because the homepage sorts by `created_at desc` on every page load and would otherwise sort the whole table.
  - **`link_target` design:** an internal `text` column, not a second enum. `'registration'|'speakers'|'agenda'|'sponsors'|'posters'` (an internal page, resolved through `PAGE_ROUTES`) or `'none'` or `'custom'`; `custom_url` is populated **only** for `'custom'` and is explicitly nulled for every other option, so a stale URL can never outlive its selection. Deliberately NOT a foreign key to the nav: routes are presentation-layer detail that should be editable in one place without a migration.
  - **RLS rationale:** with a static export the publishable key is in a public JS bundle, so RLS is the *only* thing between the internet and the write path — load-bearing, not defence-in-depth. Anonymous visitors get `for select … using (published = true)` and **no write policy at all**, so writes are denied by default rather than by an explicit deny. Authenticated users get `for all using (auth.role() = 'authenticated')` with a matching `with check`; `auth.role()` reads the verified JWT claim and is NOT `user_metadata` (which the account owner can edit, and would therefore be a spoofable authorization input). `shouldCreateUser: false` on the magic link means the login form cannot provision accounts or probe which addresses are registered, and the confirmation text is identical either way so it cannot leak who is allowlisted.
  - **`custom_url` is validated, not trusted:** `announcementHref()` accepts only absolute `http(s)` URLs and returns `null` otherwise, so a stored `javascript:`/`data:` URL can never reach an `href` (stored XSS). RLS cannot protect against this — the row itself is legal to write. The form also refuses to submit an unusable custom URL rather than silently saving a row that renders with no arrow.
  - **Shared client-side route map** lives once in `lib/announcements.ts` (`CATEGORY_LABELS`, `PAGE_ROUTES`, `announcementHref`, `formatAnnouncementDate`), imported by both the homepage renderer and the admin dropdown, so a category cannot render under two different names. **Route paths confirmed against the real `app/` dirs** — `registration|speakers|agenda|sponsors|posters` all exist, so the supplied map was used as-is (no `/program/speakers`-style rewrite needed). `'general'` is deliberately NOT a valid `link_target`: a catch-all bucket, not a page.
